# 1. 文件目的

本文件定義「個人健康檢查管理平台」的完整產品規格，包含：

1. 技術規格文件
2. 非技術規格文件
3. 醫療安全與內容治理原則
4. 中醫與命理產品邊界
5. 驗收條件與測試案例
6. Codex／Claude Code 分階段開發計畫

本產品的核心不是「AI 看完健檢報告後直接告訴使用者怎麼治療」，而是：

> 將多年健檢資料整理成可追溯的健康紀錄，建立可驗證、可停止、可調整的健康行動計畫，持續追蹤執行情況、結果與不舒服事件，並在資料不足、沒有改善或出現安全疑慮時，協助使用者整理資料供合適的專業人員進一步評估。

# 2. 產品定位

## 2.1 核心價值

使用者可以：

- 上傳歷年年度健檢報告
- 上傳每季抽血、驗尿或其他追蹤報告
- 將不同醫療院所、不同格式、不同年度的資料整理在同一個健康專案
- 查看長期趨勢
- 確認 AI 自動讀取的數值
- 依據可信來源取得健康衛教
- 建立可檢討的健康行動計畫
- 記錄飲食、活動、睡眠、疼痛與不舒服
- 檢查計畫是否有效、無效、不可判斷或造成不良反應
- 產生看診摘要
- 將必要資料分享給專業人員

## 2.2 產品不是什麼

本產品不是：

- 疾病診斷工具
- 自動開藥工具
- 自動停藥或調整劑量工具
- 緊急醫療服務
- 命理健康預測工具
- 紫微斗數疾病預測工具
- 醫師替代品
- 中醫師替代品
- 用單一 BMI 或單次健檢數字決定運動計畫的工具

# 3. 目標客群

## 3.1 核心客群：50–65 歲本人

特徵：

- 已累積多年健檢報告
- 可能開始出現血糖、血脂、體重、體脂、尿酸、肝腎功能或血壓等風險
- 能自行使用手機或電腦
- 不一定熟悉醫學名詞
- 可能同時接觸醫師、中醫、保健品與網路資訊
- 希望知道長期變化，而不是只看單次結果
- 願意為資料整理、人工審閱或專業服務付費

## 3.2 次要客群：35–50 歲成年子女

可能角色：

- 替父母整理報告
- 協助上傳與確認資料
- 協助預約或付款
- 陪同執行健康計畫
- 協助管理多位家庭成員

此族群的代理權限、授權、撤銷與通知功能列為 MVP 後續階段。

## 3.3 65 歲以上使用者

介面需預先支援：

- 大字模式
- 高對比
- 清楚按鈕
- 少步驟流程
- 不只靠顏色表示狀態
- 明確上一頁
- 防止重複提交
- 可列印摘要

語音操作、照顧者模式與極簡模式列為後續版本。

# 4. 商業目標與成功標準

## 4.1 商業目標

- 建立使用者願意長期累積的個人健康資料庫
- 讓使用者在 10 分鐘內完成第一份健檢報告匯入
- 建立可信、可追溯、有來源的健康理解體驗
- 提升長期回訪與持續上傳率
- 為未來人工審閱、專業協作與付費服務建立基礎
- 避免透過恐懼或錯誤預測促進付費

## 4.2 第一版成功指標

| 指標 | 目標 |
|---|---:|
| 註冊後成功建立健康專案 | ≥ 80% |
| 建立專案後上傳第一份報告 | ≥ 65% |
| 上傳後完成資料確認 | ≥ 70% |
| 一般清晰報告欄位擷取準確率 | ≥ 90% |
| 使用者確認後正式資料正確率 | ≥ 99% |
| AI 重要敘述含可檢視來源 | 100% |
| AI 第一段內容開始顯示時間 | P95 ≤ 3 秒 |
| 健康戰情查詢時間 | P95 ≤ 2 秒 |
| 重大跨帳號健康資料洩漏 | 0 件 |

# 7. 核心使用流程

## 7.1 首次使用

1. 註冊或 Google 登入
2. 建立健康專案
3. 填寫基本資料
4. 選擇健檢報告
5. 上傳前預覽
6. 確認目前專案與檔案
7. 上傳
8. 等待系統處理
9. 核對辨識結果
10. 修改錯誤欄位
11. 確認並納入分析
12. 查看健康戰情
13. 建立行動計畫
14. 設定回報與檢討時間

## 7.2 後續追蹤

1. 使用者定期回報
2. 系統追蹤領先指標
3. 記錄疼痛、不舒服與可持續程度
4. 到期進行檢討
5. 新健檢資料加入後重新評估
6. 結果分類
7. 維持、調整、暫停、停止或轉介

# 8. 健康行動閉環

完整閉環：

**健檢資料 → 問題辨識 → 證據與衝突說明 → 安全檢查 → 小步驟行動計畫 → 日常回報 → 定期檢討 → 維持／調整／停止／轉介 → 下一次健檢重新驗證**

## 8.1 指標分類

### 領先指標

較早反映計畫是否被執行：

- 每週活動次數
- 每次活動時間
- 飲食調整完成率
- 睡眠時間
- 疲勞
- 疼痛
- 心悸
- 胃部不適
- 計畫難度
- 可持續程度

### 結果指標

需要較久才會改變：

- 血糖
- 血脂
- 尿酸
- 肝腎功能
- 體重
- 體脂
- 腰圍
- 血壓
- 後續健檢數值

### 安全指標

- 新的或加重的疼痛
- 腫脹
- 行走或功能改變
- 頭暈
- 昏厥
- 胸部不適
- 異常呼吸困難
- 明顯睡眠惡化
- 心悸
- 飲食後持續不適

# 9. 無改善處理規則

## 9.1 禁止行為

沒有改善時，系統不得：

- 責怪使用者
- 自動增加運動強度
- 自動增加飲食限制
- 自動增加保健品
- 自動修改藥物
- 宣稱一定有其他疾病
- 無限期要求繼續
- 把沒有改善等同「沒有遵照」

## 9.2 標準檢討流程

1. 確認安全
2. 確認資料是否可比較
3. 確認實際執行情況
4. 確認是否達到合理觀察時間
5. 檢查睡眠、壓力、疾病、用藥與生活變化
6. 分類結果
7. 決定下一步

## 9.3 結果分類

- 有改善
- 部分改善
- 暫時穩定
- 尚未到檢討時間
- 執行資料不足
- 測量資料不可比較
- 計畫可能無效
- 計畫難以持續
- 出現不良反應
- 需要專業評估

# 10. 情境呈現規格

不使用：

- 最佳狀況
- 一般狀況
- 最差狀況

改為：

## 10.1 有效且安全

顯示：

- 哪些領先指標先改善
- 哪些結果可能需要較久
- 何時值得維持
- 哪些結果不能保證

## 10.2 尚未有效或無法判斷

顯示：

- 是否已到檢討日期
- 執行是否可持續
- 資料是否可比較
- 是否需簡化、替換或補資料

## 10.3 出現不適或需要升級處理

顯示：

- 哪些行動應暫停
- 哪些症狀需記錄
- 是否需要專業評估
- 禁止自動增加強度

# 11. 飲食建議規格

## 11.1 必要背景

- 過敏
- 慢性疾病
- 懷孕
- 用藥
- 特殊飲食
- 宗教文化
- 胃腸道不適
- 飲食失調風險
- 成本與可取得性

## 11.2 水果相關

- 區分完整水果、果汁、果乾、糖漬水果、果醬與加糖飲品
- 不把「甜」直接等同「有害」
- 不把基因改造直接等同健康風險
- 不宣稱所有人都適合或不適合空腹吃水果
- 必須顯示份量與食用情境
- 有血糖管理需求時標示不確定性
- 不鼓勵極端排除整類食物
- 持續不適時停止計畫並重新評估

## 11.3 咖啡相關

- 不要求原本不喝咖啡的人開始喝
- 記錄咖啡因、份量、時間與添加物
- 同時追蹤睡眠、胃部不適、心悸與焦慮
- 顯示研究是否一致
- 不把統計關聯當成確定因果
- 不把咖啡當成治療方式

# 12. 運動安全規格

## 12.1 禁止只依 BMI 推薦

不得只根據以下資料推薦跑步或高強度活動：

- BMI
- 體重
- 體脂
- 單次血壓
- 單次健檢結果

## 12.2 運動前必要資訊

- 過去三個月活動情況
- 胸部不適
- 昏厥
- 異常呼吸困難
- 肌肉、肌腱或關節疼痛
- 舊傷
- 手術史
- 慢性疾病
- 用藥
- 平衡與跌倒史
- 醫師限制
- 場地與器材
- 使用者喜好

## 12.3 運動計畫內容

- 活動類型
- 起始強度
- 每次時間
- 每週頻率
- 熱身與恢復
- 肌力、心肺、平衡與活動度
- 進階條件
- 暫停條件
- 疼痛紀錄
- 疲勞與恢復
- 下次檢討日期

## 12.4 疼痛處理

使用者可記錄：

- 疼痛位置
- 發生時間
- 執行動作
- 是否影響日常活動
- 是否腫脹
- 是否惡化
- 是否休息後改善

若疼痛新出現或加重：

1. 暫停相關活動
2. 不自動改成更高強度替代動作
3. 顯示安全提示
4. 產生專業評估摘要
5. 保留事件
6. 將計畫標示為暫停或因不良反應停止

# 13. 醫學知識與衝突處理

## 13.1 來源優先順序

1. 政府衛生與醫療機關
2. 國際公共衛生組織
3. 專業醫學學會
4. 同行審查指南或系統性回顧
5. 經審核的醫療院所衛教內容

## 13.2 每個醫學主張需保存

- 族群
- 行動或曝露
- 份量
- 比較對象
- 結果
- 研究方向
- 研究類型
- 適用條件
- 風險
- 不確定性
- 發布日期
- 來源版本
- 是否撤回

## 13.3 衝突狀態

- 大致一致
- 條件不同
- 證據混合
- 證據不足
- 不適用本人
- 來源過期
- 來源撤回

## 13.4 AI 呈現要求

遇到衝突時，回答必須包含：

1. 相對一致的部分
2. 有爭議的部分
3. 研究不同的可能原因
4. 與使用者相關的條件
5. 缺少資訊
6. 低風險選項
7. 何時尋求專業協助

# 14. 中醫模組產品邊界

## 14.1 發展順序

### T1：中醫文化與健康衛教

可包含：

- 中醫基本概念
- 古典文獻歷史背景
- 中醫名詞
- 傳統飲食文化
- 中西醫觀點差異
- 中藥安全注意事項
- 就診前問題整理

限制：

- 不替使用者辨證
- 不判定體質
- 不依健檢推薦藥材
- 不提供方劑與劑量
- 古籍不可當成現代臨床證據
- 內容需由合格中醫師審閱後公開

### T2：中醫師人工報告審閱

需要：

- 中醫師資格驗證
- 使用者資料分享同意
- 最少必要資料
- 審閱紀錄
- 專業人員簽核
- 服務取消與退款規則
- 人工審閱與正式診療區隔

### T3：實際辨證與開方

需另行建立：

- 合法醫療合作模式
- 合格中醫師
- 正式問診
- 病歷
- 處方責任
- 中藥來源
- 調劑
- 不良反應
- 中西藥交互作用
- 緊急轉介
- 法律與責任保險

AI 只能協助整理，不得成為開方者。

## 14.2 中醫資料分享

預設分享：

- 使用者選擇的健檢項目
- 日期範圍
- 用藥摘要
- 過敏
- 疾病背景
- 本次問題
- 最近不舒服或生活紀錄

預設不分享：

- 全部原始 PDF
- 全部 AI 對話
- 無關家庭資料
- 身分證件
- 其他專業人員完整紀錄

# 15. 紫微斗數與命理產品邊界

紫微斗數必須：

- 另做獨立網站
- 另做獨立品牌
- 使用獨立資料庫
- 使用獨立隱私政策
- 不取得健檢報告
- 不取得病史與用藥
- 不產生健康風險
- 不參與飲食、運動或就醫優先級
- 不利用疾厄宮、流年或流月預測疾病
- 不用命理焦慮推動付費醫療服務

允許：

- 命盤文化介紹
- 年度反思
- 日記
- 非醫療性生活提醒
- 普遍性例行健康提醒連結

# 18. 狀態機

## 18.1 健檔文件

```text
selected
  → previewed
  → uploading
  → uploaded
  → processing
  → review_required
  → confirmed

uploading → upload_failed → uploading
processing → processing_failed → processing
review_required → processing
confirmed → review_required
任一非刪除狀態 → deleting → deleted
```

## 18.2 AI 訊息

```text
queued
  → retrieving_sources
  → safety_check
  → streaming
  → completed

queued/retrieving_sources/safety_check → blocked
任一處理狀態 → failed
streaming → cancelled
failed/cancelled → queued（建立新版本）
```

## 18.3 健康行動計畫

```text
draft
  → needs_info
  → safety_review
  → active
  → review_due

active → paused
paused → active
active → stopped_due_to_adverse_event
active → review_due
review_due → active
review_due → adjusted
review_due → completed
review_due → ineffective
review_due → escalated
adjusted → active
任一非刪除狀態 → archived
archived → deleted
```

強制規則：

- 因不良反應停止後不得自動重新啟用
- 無效不得自動增加強度
- 調整建立新版本
- 所有 AI 產生的計畫草稿必須 Streaming
- 串流完成不代表計畫已啟用，仍需使用者確認

# 19. 資料持久化

- 所有功能以健康專案形式保存
- 使用者可重新登入後續編
- 表單自動儲存
- 上傳中斷可重試
- AI 串流中斷保存已完成內容與狀態
- 正式檢驗紀錄修改建立新版本
- 行動計畫修改建立新版本
- AI 報告保存個人資料版本與知識版本
- 舊專案在系統升級後仍可開啟
- 可修改物件包含 version
- 多分頁衝突不得靜默覆寫

---

# 20. 檔案與縮放規則

- 所有上傳功能必須提供預覽
- 上傳前可取消
- 文件與圖片縮放保持原始寬高比
- 不拉伸、不壓扁、不用裁切填滿
- 大檔可重試或分段上傳
- 重複提交不得建立重複文件
- 檔案下載使用短效授權
- 驗證實際內容，不只副檔名
- 執行惡意檔案掃描

---

# 21. AI 規格

## 21.1 強制要求

- 所有語言模型輸出必須 Streaming
- 僅使用目前專案已確認資料
- 僅使用有效知識來源
- 個人結論需引用個人資料
- 醫學敘述需引用知識來源
- 資料不足時明確說明
- 禁止虛構來源
- 禁止診斷式語言
- 禁止藥物劑量、停藥或治療保證
- 使用者可取消、重新產生與回報問題
- 串流中斷建立失敗狀態，不覆蓋舊版本
- 使用者輸入與文件內容皆視為不可信
- 日誌不得記錄完整健康內容與完整 Prompt

## 21.2 回答結構

1. 現有資料摘要
2. 觀察到的變化
3. 可能相關的一般因素
4. 限制與不確定性
5. 可考慮的低風險行動
6. 建議詢問專業人員的問題
7. 引用來源
8. 安全提醒

- 重複提交不重複建立
- 不支援格式有明確提示

## 28.4 辨識

- 每個欄位可回查原始頁面

- 未確認資料不進正式趨勢

- 可建立、修改、暫停、恢復、刪除
- 日常回報可新增、修改、刪除
- 新健檢資料加入後觸發重新檢討
- 無改善不自動增加強度
- 不良反應時立即暫停
- 調整建立新版本
- 可產生專業轉介摘要

# 32. 非技術版說明

這是一個幫你整理多年健康檢查資料的網站。

你可以把每年的健檢報告，或每三個月一次的抽血、驗尿結果放進網站。網站會把不同日期的結果排在一起，讓你看見哪些數值正在改變，以及哪些資料值得下次看醫師時提出。

網站讀取報告後，不會直接把所有資料當成正確。你需要先核對內容。只有你確認過的資料，才會正式進入健康分析。

網站提出的每一項行動，都會告訴你：

- 為什麼提出
- 哪些情況可能適合
- 哪些情況不適合
- 要先做多久
- 要觀察什麼
- 何時檢討
- 沒有改善時怎麼辦
- 出現不舒服時何時停止

沒有改善不代表你失敗。

網站會先檢查：

- 資料是否可以比較
- 計畫是否做得到
- 是否已經執行足夠時間
- 是否有睡眠、壓力、疾病或其他變化
- 是否出現不舒服
- 這個方法是否可能不適合你

網站不會因為沒有改善，就自動叫你吃得更少或運動更多。

網站也不會：

- 替你診斷
- 告訴你停藥
- 幫你改藥
- 依命盤判斷疾病
- 因為 BMI 高就直接叫你跑步
- 保證照做三個月後一定改善

# 35. 最終結論

產品的正確資料鏈為：

**原始健檢報告 → 預覽 → 自動讀取 → 人工確認 → 正式健康紀錄 → 長期趨勢 → 證據與不確定性 → 可停止的健康行動計畫 → 日常回報 → 定期檢討 → 維持／調整／停止／轉介 → 有來源的 Streaming 健康摘要**

本產品成功的關鍵，不是 AI 回答得像不像醫師，而是：

- 每個數值都能回到原始報告
- 每個建議都有來源、限制與停止條件
- 沒有改善時不責怪使用者
- 出現傷害時不自動加強
- 中醫與命理不污染健康決策
- 所有資料可持久化、續編、修改、刪除與匯出
